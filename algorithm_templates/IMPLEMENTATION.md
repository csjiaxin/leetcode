# 统一模板、独立题解与文档验证

本轮按各系列 README 的不变量重写实际题解，并将所需模板放进每道题的 `.go` 文件。复制单题源码即可获得完整的模板与适配器，无需导入本仓库的算法包或再拼接 `template.go`。

## 代码与 README 的对应关系

1. 每个系列先给出固定模板，说明状态、初始化、依赖顺序和更新不变量。
2. 每道题只适配输入转换、合法操作、状态转移与答案聚合；不同不变量使用不同子模板。
3. README 为阅读方便只声明一次模板，再展示逐题适配器；实际题解复制自己所需的模板，官方接口实现可用于提交，历史接口变体在文档中单独标明。
4. 不同题的 Constructor、rob、maxProfit 等同名入口分别提交。平台已提供节点类型时沿用平台定义。
5. 历史推导与旧代码保留在各系列 legacy 笔记中，当前实现以主 README 和题目 `.go` 为准。少量原模板文件保留作参考及模板测试入口，题解不依赖这些文件。

仓库的 `package l题号` 用于本地测试。提交到 LeetCode 编辑器时省略该包声明，保留所需标准库 import、官方入口及文件内模板；平台已提供的节点类型不重复声明。

## 验证结果

- `go test -count=1 ./...`：320 个有测试的包通过，另外 60 个包编译通过，没有失败包。
- 将 364 个题解源文件分别复制到独立临时包，逐文件编译全部通过，避免依赖同目录的辅助文件。
- 题解源码中没有 `leetcode/...` 仓库内部算法包导入。
- 五个根系列 README 中的 94 个适配器从文档重新组装；通过现有题目测试。没有原测试的 Trie 题另用独立样例及随机穷举对照验证。
- DP 七个家族 README 的 59 个适配器由文档重组后，通过原题目测试。
- 序列、窗口、栈、回溯、排列与贪心的 11 份 README，118 个 Go 代码块按各页说明组合后可编译。
- 图算法 README 的 49 组模板与适配器重新组装成独立包，其中 25 包通过原测试，另外 24 包编译通过；覆盖 BFS、并查集、Dijkstra、Kahn、网格连通块、Prim 和 Floyd。
- 另外用穷举验证 1856、2281、1574：每题覆盖 5,461 个小规模数组；二进制 Trie 与直接枚举进行固定种子的随机对照。

上述全量 Go 命令覆盖根 `go.mod` 模块；AVL、红黑树的历史库位于独立嵌套模块，本轮未修改，其运行边界见树系列文档。

这些验证区分了题目测试、独立单文件编译与 README 代码重组；编译成功不等同于 LeetCode 在线评测通过。少量历史接口变体保留原契约，例如 DFS 130 返回副本并保留输入，官方原地接口应选择图 BFS 130。无测试包的编译成功也不等同于覆盖所有题意边界。

## 测试资料修正

本轮保留题目入口与原测试的主体，只修正两处由独立计算证实错误的旧预期：

- 703 的模板变体：初始 `[4,5,8,2]`、k=3，依次加入 `[3,5,10,9,4]` 的第三大值为 `[4,5,5,8,8]`。原第三项误写成 8，现改为 5；用逐步排序独立核对。
- 907 的模板变体：输入 `[11,81,94,43,87]` 的子数组最小值之和为 656。原 444 对应末项为 3 的另一输入，现只修正预期；用枚举所有子数组独立核对。

新增的五份小型测试针对补全的 300、343、474、1039、174，覆盖其状态边界与典型反例。没有为满足错误预期而在算法中添加特例。
