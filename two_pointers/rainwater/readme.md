## 2. 11：选择两个边界，面积最大

```text
area(l,r) = min(height[l],height[r]) × (r-l)
```

- 只选两个端点，中间柱子不从容量中扣除。
- 求一对边界的最大面积，不是逐位置累加。
- **移动短板**：固定较短端点，仅向内移动另一端，宽度变小，高度上限不能增大，因此不可能得到更大面积。
- 两端等高时移动任意一边即可；移动短板只保留变好的可能，不保证下一步面积增大。

时间 O(n)，额外空间 O(1)。实现与测试：[11.go](../l11/11.go)、[11_test.go](../l11/11_test.go)。

## 3. 42：一维接雨水，同一道题学习三种方法

位置 i 的积水量：

```text
water[i] = min(leftMax[i],rightMax[i]) - height[i]
```

两侧最大值均包含当前位置，因此结果非负。最终答案是所有位置水量之和。

### 3.1 前后缀最大值：按位置计算

```text
leftMax[i]  = max(height[0...i])
rightMax[i] = max(height[i...n-1])
```

先求两个数组，再逐位置累加。时间 O(n)，额外空间 O(n)，最适合建立水位公式的直觉。

### 3.2 双指针：结算水位已确定的位置

维护左右已扫描区域最高柱 leftMax / rightMax，每轮先更新两侧最高值：

- leftMax <= rightMax：右侧已经存在足够高的挡板，结算左侧并 l++。
- 否则结算右侧并 r--。

这是前后缀最大值思路的空间优化，时间 O(n)，额外空间 O(1)。

实现：[42.go](../l42/variants/from_rainwater/42.go)、[练习目录](../l42/42.go)。详细双指针模板与图解见[双指针总结](../readme.md#leetcode-42)。

### 3.3 单调栈：按凹槽层计算

维护高度单调不增的柱子下标；当前柱子更高时，弹出凹槽底部。如果弹出后栈空，说明没有左边界，不能结算。

```text
左边界          右边界
   |               |
   |     底部      |
   |______|________|

宽度 = 右边界下标 - 左边界下标 - 1
高度 = min(左右边界高度) - 底部高度
新增水量 = 宽度 × 高度
```

```go
func trap(height []int) int {
	stack := make([]int, 0, len(height))
	water := 0
	for right, h := range height {
		for len(stack) > 0 && h > height[stack[len(stack)-1]] {
			bottom := stack[len(stack)-1]
			stack = stack[:len(stack)-1]
			if len(stack) == 0 {
				break
			}
			left := stack[len(stack)-1]
			level := height[left]
			if h < level {
				level = h
			}
			water += (right - left - 1) * (level - height[bottom])
		}
		stack = append(stack, right)
	}
	return water
}
```

每个下标最多入栈、出栈一次，时间 O(n)，额外空间 O(n)。

| 方法 | 计算视角 | 时间 | 额外空间 |
|---|---|---|---|
| 前后缀最大值 | 每列水量 | O(n) | O(n) |
| 双指针 | 每列水量，动态确定上限 | O(n) | O(1) |
| 单调栈 | 每层凹槽水量 | O(n) | O(n) |

与 84 对照：42 在左右较高柱子之间计算水层；84 为每根柱子寻找左右更矮边界，计算以它为高度的矩形。

## 4. 407：二维接雨水，边界最小堆

二维不能简单求上下左右四个直线方向的最高墙，因为水可能拐弯，沿低通道逃到边界。

```text
5 5 5 5 5
5 1 1 1 5
5 1 5 1 5
5 1 1 1 1  ← 连通边界的低通道
5 5 5 5 5
```

### 从最低的有效边界向内扩张

1. 所有外围格子加入最小堆，去重并标记访问。
2. 弹出当前最低的有效边界。
3. 查看未访问的四邻格；地面低于边界时累加水量。
4. 邻格按新的有效高度入堆，入堆时标记访问。

```go
// 从堆中弹出边界 cell 后，对未访问邻格执行：
water += max(0, cell.height-heightMap[nr][nc])
nextHeight := max(cell.height, heightMap[nr][nc])
// 将 (nr, nc, nextHeight) 加入最小堆。
```

**入堆的是有效边界高度，不一定是原始地面高度。** 例如边界为 5、邻格地面为 2，新增水量为 3，邻格入堆高度应为 5，而不是 2；填入的水形成后续扩张的水位边界。

时间 O(mn log(mn))，额外空间 O(mn)。完整最小堆实现及测试已在仓库中：[407.go](../../heap_priority_queue/l407/407.go)、[407_test.go](../../heap_priority_queue/l407/407_test.go)。

| 一维 42 | 二维 407 |
|---|---|
| 只能向左或向右逃逸 | 可沿任意四连通路径逃逸 |
| 维护左右边界 | 维护整个扩张前沿 |
| 比较左右最高值 | 最小堆选择最低有效边界 |

**双指针不能直接推广到二维，但“先处理较低有效边界”的思想可以推广。**

## 5. 778：水位上升与瓶颈路径

问水位至少达到多少，才能从左上角走到右下角。对一条路径而言，所需最低水位就是路径上的最高地面高度：

```text
答案 = min（所有起点到终点路径上的最大高度）
```

这是 minimax / 瓶颈路径，不是路径高度之和最小。

### Dijkstra 的转移

```text
普通最短路：candidate = dist + edgeWeight
778 瓶颈路径：candidate = max(dist, grid[nr][nc])
```

778 起点标签为 `grid[0][0]`，不是 0。

- 最小堆 Dijkstra：时间 O(n² log(n²))，额外空间 O(n²)。
- 二分水位 + BFS/DFS：给定水位，判断仅经过不高于该水位的格子能否连通，判定具有单调性。
- 并查集：按高度从低到高激活格子，与已激活邻格合并，直到起终点连通。

### 与 407 的统一视角

两题都关心“沿路径通过时，最高障碍有多高”：

- **778**：从起点到终点，找瓶颈最小的路径。
- **407**：从每个格子到任意外边界，找最低逃逸水位，再减去地面高度。

形式上，407 中格子 v 的水位是：

```text
level(v) = min（v 到任意外边界的路径上的最大地面高度）
water(v) = level(v) - height(v)
```

因此 407 可视为多源、从外向内的瓶颈路径扩张。参考[单源最短路笔记](../../graph/single_source_shortest_path/README.md)。

## 6. 755：有限水量，逐滴模拟

42 / 407 假设水足够多，计算最终能留多少水；755 指定倒水位置 k 和有限水量 volume，每滴水落下都会改变当前高度。

每滴水按规则：

1. 优先向左寻找能降低落点高度的位置。
2. 左边不能降低，再向右找。
3. 两边都不能降低，就留在 k。

扫描时可以经过等高平台继续找低处，但不能跨过上坡。实现时只在遇到严格更低高度时更新候选落点，遵守平台上的停留规则。

通常逐滴模拟时间 O(volume × n)，额外空间 O(1)，不计返回数组。**不能套用 42 的最终水位公式，因为水不一定足够填满凹槽。**

## 7. 1488：降雨与抽水调度

雨天让一个湖泊装满；晴天可以抽干一个湖泊。满湖再次降雨就会泛滥。

```text
rains = [1,2,0,0,2,1]
             ↑ ↑
             晴天
```

需要在湖泊两次降雨之间安排抽水。这里每次降雨对应湖泊状态变化，不涉及柱子高度或水量累加。

两种常见贪心解法：

- **有序集合**：重复降雨时，选择上次降雨之后、当前之前最早可用的晴天。记录之前的晴天下标，查找严格大于上次降雨日的最小下标。
- **最小堆**：预先计算下一次降雨时间；晴天优先抽干下一次降雨最早的满湖。

使用支持对数查找与删除的数据结构时可做到 O(n log n) 时间、O(n) 空间。Go 标准库没有通用有序集合，可选择最小堆方案；仅用切片二分再删除不能保证 O(n log n)。

**这是贪心调度问题，不是双指针或接雨水地形问题。**

## 8. 扩展题的迁移点

### 799：香槟塔——溢出 DP

每个杯子容量为 1，超过部分等分流向下一层两个相邻杯子：

```text
overflow = max(0, amount-1) / 2
下一层左杯 += overflow
下一层右杯 += overflow
```

杯内流入量可以大于 1，最终查询答案才截断到 1。查询第 r 行时，逐层 DP 时间 O(r²)，滚动数组额外空间 O(r)。

### 365：水壶问题——数学可达性

容量为 x、y，允许装满、倒空、相互倒水。标准题意下，目标水量 target 可实现的条件为：

```text
target == 0，或
同时满足 target <= x+y 且 target % gcd(x,y) == 0
```

这里按题目约束 x、y 为正数；推广到零容量需要单独处理 gcd 为 0 的情况。欧几里得算法时间 O(log(min(x,y)))、额外空间 O(1)。也可用状态搜索理解操作的可达性。

## 9. 易错点与练习路线

### 易错点

- **11 和 42 混淆**：11 选一对边界，42 累计每个位置的水量。
- **只看邻接柱子**：42 需要两侧最高柱，不是左右紧邻高度。
- **二维只看四条直线**：407 的水能沿弯曲通道逃逸。
- **407 按地面高度入堆**：应按 `max(当前有效边界,邻格地面)` 入堆。
- **778 用高度相加**：瓶颈路径取 max，不求和；起点高度必须计入。
- **755 当作无限降雨**：有限水量必须遵守逐滴流动与方向优先规则。
- **1488 晴天随便抽**：必须保留未来可行性，按可用日期或下次降雨期限贪心。

### 推荐路线

```text
11 容器
   ↓ 区分选边界与累计积水
42 接雨水
   ├── 前后缀最大值
   ├── 双指针
   └── 单调栈 → 84 最大矩形（对照边界含义）
   ↓ 推广到二维
407 接雨水 II
   ↓ 最小堆与瓶颈路径
778 水位上升的泳池中游泳

独立分支：
755  倒水       → 有限水量模拟
799  香槟塔     → 逐层溢出 DP
1488 避免洪水   → 抽水时间调度

```

优先掌握 **11、42、407、778**，尤其是 **42 → 407 → 778** 的思想迁移。
